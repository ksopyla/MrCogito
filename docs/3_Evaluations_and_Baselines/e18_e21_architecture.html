How information flows: E18 vs E21

Same backbone in nn/perceiver_ar_lm.py: hashed embed → sliding-window pre-encoder → one global read → local stack → LM head. The split is that global read. Toy row: S=48, QUERY at t=32, r=16 → 2 sender slots. Not a new experiment — this is the architecture that ran.

Compute / memory. E18 and dense attend the sequence on the unbounded layer(s): global KV length = S (~1 KB/token at 2 kv-heads × 128 dims, bf16 — E18 main). E21, after QUERY, attends a small exclusive slot set (~S/r keys, r=16 → ~64 B/token) plus raw keys on the receiver side. Local SWA is bounded either way. E21 is not a reasoning tower: extra slot hops default to 0; slots are class-r mean pools, not a latent thinker.

Honest limits (from the specs and the code)

  • Family is perceiver_ar in nn/perceiver_ar_lm.py. nn/concept_encoder_perceiver.py is a different (concept-MLM) stack — not this diagram.
  • E18: [SWA] × pre → [full causal] × 1 → [SWA] × stack. Global K/V = raw prefix, KV_LEN = S. Dense control (par_mode=dense) makes every layer full-S.
  • E21: message_boundary_token_id (DNA query) splits sender | receiver. KVCompressor emits one slot per complete homogeneous block of r=16. Receiver global read: exclusive slots ∪ same-side raw. Default extra hops = 0, remainder pooling off, anchors off.
  • Inplace (DNA walls after concat failed): slots scatter onto sender positions; exclusive mask hides uncompressed leftover. Concat (original E21 spec): KV = raw ‖ slots, KV_LEN = S + nb.
  • r=16 class slots, not a latent reasoning tower. E19 write-back / extra slot attends / second global layer are other knobs, off here.
