E33t Catalogue Read

The notes stop being read and become a catalogue: they only decide which original tokens each query opens. Every token is filed under one balanced note, the catalogue is trained by where the read's attention actually lands, the 512-token budget is filled by tokens, and each of the four loop passes opens notes the query has not opened yet. A second arm searches pages first, then notes. Check that this page says what you mean, then return the checklist at the end.

2 · A worked example: a two-step lookup

A 40-token row in five 8-token pages, at toy scale: a window of 8 tokens (for 512), 4 notes per page (for 32), a budget of 4 opened tokens per pass (for 512), balanced notes of 2 tokens, capped at 3. The query is the last token; the next token is “seven”. To get it, the model must find who Voss's ship is (page 1) and then that ship's code (page 3). Filing and scores are hand-built to illustrate; only the rules are real.

    3 · Who may attend to what

    The reading layer's mask for the toy row: queries down, keys across. A query may read the 4 empty slots, its last 8 tokens, and the tokens it opened in this pass: only from closed pages of its own document, only tokens older than its window, never the future. Switch the pass to see the opened set move.
