Our catalogue read is within a few points of LSA, and ahead of it at 128k

We changed how the model looks things up in its notebook. The notes no longer get read; they only point to the exact words worth rereading, like cards in a library catalogue. At 30M parameters it now recovers 91 % of what rereading every page gives at 16k tokens (our previous design: 39 %), is level with the LSA reference read at 64k, and has the lowest 128k loss of any model we trained.

How much of the full-reread benefit each model recovers

Think of a student reading a long book. The window control only sees the last few pages (0 %). The dense model may reread any page at any time (100 %). Each model's score is the share of that gap it closes on words more than 2k tokens into a document. Past 16k the dense model is reading longer documents than it was trained on and gets worse, so scores above 100 % are possible there.

What we learned

Stage A

Letting each pass revisit notes closed most of the gap

The first catalogue made each of its four reading passes look somewhere new: 71 % at 16k. Dropping that rule in training, nothing else changed, lifted it to 91 %. On a planted password the later passes now return to it 95–97 % of the time at 4k, as LSA's do.

Stage A

Two-level search holds at 16k, slips at 64k

Searching pages first and then the notes inside them keeps the search cost growing with pages, not words. It is 3 points behind the flat search at 16k but 16 behind at 64k, well outside the 5 points we allowed.

Stage B

32 or 64 notes per page is a near-tie; 16 is too few

64 notes won by the rule written before the runs (88 vs 86 % on the same machine), but the margin is a third of the hardware gap. 16 notes lost 18 points. 512-token pages sat 2–4 points behind, with the best needle-puzzle score.

Stage B

Home and AWS runs differ by about 5 points

The same model, seed and recipe scored 91 % on AWS and 86 % on Odra, and the control models shift too. Comparisons are only fair between models trained on the same machines.

Stages A–B

No harm to general knowledge

Seven short benchmarks average 40.1–41.0 % for every AWS-trained model, the window control 40.8 %. Home-trained models score 38.9–39.9 %, which is the hardware gap again, not the notebook.

Stage C

Past 128k the notebook still helps, but nobody finds the password

Trained only on 16k documents, the 64-notes model predicts 256k documents better than both the window control and LSA. With its notebook removed it falls just below the window control, so the gain is the notebook's. At 128k and 1M no model gets more than 2 of 20 passwords.
