E37f — closed-book practice for concept memory

Concept memory rereads the best 512 far tokens word for word and sees every other concept only as one averaged summary. Today those summaries alone are worse than cutting the document. The bet: if some training rows may open nothing, the model must learn to write summaries that hold the document. A retrofit of the released 150M model on Odra, about one day, no AWS money.

Information budget along the path

One concept (about 8 tokens)

A summary keeps 64 numbers of value for 8 tokens' 512: one eighth. Raw room is not the limit (64 numbers can hold 8 tokens' identities, about 125 bits); what an average keeps depends on how the layers below write the values. The reasoner reads the concept's mean state (896 numbers) and writes a 64-number update.

Window: the query's own block and the one before (512–1,024 tokens). In a closed-book row the opened column is zero and those concepts are read as summaries too. At 10M the summaries carry essentially everything, which is why they must hold content (and why a concept tree is needed for their count, a later spec).

Rules that do not change

  • One softmax over sinks ‖ window ‖ opened members ‖ summaries; every past token counted exactly once.
  • Only closed blocks older than the window become concepts; the query's own block is read raw and causally, so no summary contains a token the query must not see.
  • A query reads only its own document's concepts; summaries never mix documents.
  • Choice of what to open: estimated attention mass (the summary logit, best head), best concept first until the row's budget is used. The budget is the only thing closed-book practice changes.
  • Reasoner (with "+ reasoner"): a concept attends to concepts of its own and earlier blocks, same document only; its update is added to the summary and to the members' values read from memory.
  • Held-out loss and every test run as trained: 512 tokens opened (plus the extra test switches).
