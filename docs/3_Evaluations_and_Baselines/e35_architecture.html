E35: two agents that talk in latent vectors

Agent A reads a long document into its memory. Agent B never sees the document: it gets K real-valued vectors from A and answers questions from them. Memory, writing to it, and sending from it are separate parts, and the message tensor is the only thing that crosses. This page shows how information flows through the four parts, what the message costs, how it is trained, and the results so far.

  • Data. Text-checks world documents. A gets the document (stories with facts woven in, 256–4,096 tokens). B gets 8 questions with answers, plus up to 4 bridge questions on compose and deduce documents. Story rows (25 % of tokens) train B alone, with an empty memory, to keep its language.
  • Loss. Next-word loss on B's tokens only. The document is never a target, so the only way to answer is through the message.
  • First runs. K = 16 with the order term (main), K = 4 (4× more compression), K = 64, and K = 16 without the order term. 3,000 steps of 96 rows (about 0.5B row tokens), step size 5e-4.

4 · How we will know the message carries the document

the real message

B answers questions about a document it never saw. Exact answer, as in the text checks, at 1k / 4k / 16k, then up to 1M tokens for lookup.

an empty message

A reads nothing. What B can guess from the question alone: must sit at the guessing rate (6–20 % depending on the task).

another document's message

The message of a different document of the same kind. If B still scores, the message was a generic hint, not this document's content (published latent-transfer results have failed this check).

Two references bracket the result. Dense reading the whole document itself scores 80–99 % at 4k: the ceiling, with no compression. E31c reading its full notebook (about 6 tokens per note) is the same memory before it is squeezed into K vectors. The Cramming probe (per-text optimized vectors for the frozen receiver) measures how many tokens one vector can carry into this receiver at all.
