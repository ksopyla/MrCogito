Latent thoughts over the E31 memory

The simplest way to add multi-hop reasoning to E31 without new parameters. After the question, the model takes a few extra "thinking" steps. Each step feeds its own output back as the next input and looks at the memory again. The memory, the writer and the reader stay exactly as they are.

The idea in one sentence. Today the question side gets one look at the memory. With latent thoughts it gets one look per hop, and each look asks with what the previous look found. That is the dependence a chain A → B → C → D needs, and the ingredient our repeated read (E33) was missing.

1 · How it works, step by step

Four chains are stored as separate facts, shuffled across the book: A→B→C→D plus three look-alike chains. The question is "start at A, where do you end?" The candidate end nodes are D, H, L and P, so guessing gives 25 %. Pick a mode and step through it. Purple cards are memory latents, one per fact, written by the E31 page encoder.

What one thought step computes

A thought position runs the unchanged E31 main path: local layer → global read (own side + memory) → two local layers. Only its input is new: the final hidden state of the previous position instead of a token embedding. The read's query is built from that input, so the second look asks about B, and the third about C.

2 · How it is trained: from written steps to latent steps

Coconut needed this curriculum: without it, latent thoughts were no better than no reasoning at all. Our data generator knows every intermediate node, so the written steps cost nothing to produce.

Stage 0 is an explicit scratchpad: the model writes the intermediate nodes as 8-letter tokens, with a loss on them, before the answer. Each later stage replaces one more written node with one latent thought. In the last stage the whole chain runs in latent space: one thought per hop instead of 8 letters per hop.

Start from
The best E31 checkpoint after its lookup and 8k stages. The memory already retrieves to 128k.
Training mix
About half reasoning exams (with thoughts) and half replay of lookup, recall and decoys (no thoughts), so retrieval cannot drift.
Two arms for the memory
Writer frozen: the memory is identical, so retrieval stays exactly the same. Writer trainable: the memory may learn to store facts in a more "followable" form.

3 · The exams: how we measure reasoning

Every exam is generated with its intermediate steps known, scored on the first answer letter (no copy inflation), and run on a length ladder. Controls must not move.

Pass marks (written before the runs)

  • Reasoning: parallel chain, 3 hops, at 1k: ≥ 75 % first letter on 2 seeds (today 40 %, dense 44 %, chance 25 %).
  • Length: at 32k with the facts in far-apart windows, ≥ 0.8× the 1k score.
  • Hop generalisation: trained on ≤ 4 hops, 6 hops with 6 thoughts ≥ 60 %.
  • No harm: lookup, recall16, decoys and the in-order chain within 2 points of today at 1k–128k. Parameter count unchanged.
  • Trace: thought t decodes node t+1 (through the output head) on ≥ 80 % of the solved questions.

Decision rules

  • Scratchpad fails (< 60 %) → the memory cannot be followed. Fix the writer first (store each edge as a source key and a target value).
  • Scratchpad passes, latent thoughts fail → the reasoning is in the tokens only. Keep the scratchpad as a fallback and try a discrete node embedding as the fed-back input.
  • Pause tokens ≈ latent thoughts → it is compute, not feedback. Move to the recurrent-core option.
  • Latent thoughts pass → next: branching reachability, typed relations, then text (BABILong-style), then reasoning inside the memory.

5 · Parameters, compute and risks

Cost per question (k thoughts)

The bars show what each part touches, not measured time. The book pass and the memory writer run once. Each thought adds one short position through four layers, plus one read over the N/6 memory entries. A first, simple implementation reruns the short question side k times; that is cheap at 1k and can be cached later.

Risks

  • Training is sequential over thoughts (each needs the previous output). It only applies to the few question-side positions.
  • Scale drift. The fed-back state is unnormalised. Use the existing final RMSNorm output (no new parameters), as Coconut does.
  • The local layers see 16 positions back. Fine for up to about 8 thoughts; the global read sees the whole question side anyway.
  • Overthinking. Extra thoughts past the needed hops may hurt. Train with a random 0–2 extra thoughts.
  • The exam may be too hard at 30M. The scratchpad arm tells us early, within the first day of runs.
