Latent reasoning: what other labs proved, and what it means for E31

Looped transformers, tiny recursive networks, continuous chain of thought, and multi-hop reasoning over memory. About 60 papers from 2024–2026, read for one question: how do we add multi-hop reasoning to a small model that reads a long document through the E31 latent memory?

The short answer. The labs agree on one thing: reasoning in latent space works when a later step can use what an earlier step found as a new input, and when every step is supervised, often with a curriculum. Looping a block over frozen inputs, without these, gives little. Our repeated read (E33) had neither, and it failed. Looping also does not add knowledge capacity: it helps use facts, not store them. That fits E31's split well. The memory stores, and a small loop on top composes. Recommendation: run a one-day diagnostic, then test "thought tokens over the memory" (option A below). It is the cheapest idea with a proof for exactly our failing task, graph reachability.
Looped transformers
Proven up to 3.5B, for math and multi-hop
A k-layer block looped L times nearly matches a kL-layer model on reasoning. It does not help memorised facts (about 2 bits per parameter either way).
Tiny recursive networks
Big wins on puzzles, nothing yet on language
7–27M models beat LLMs on Sudoku, mazes and ARC. The driver is deep supervision plus an outer refinement loop, not the hierarchy.
Continuous chain of thought
Proven for graph reachability in 2 layers
Feeding the last hidden state back as the next input lets one "thought" hold a whole frontier of nodes. It needs a curriculum from explicit steps.

1 · The problem we are solving

E31 writes a long book into latents: one 512-d latent per about 6 tokens, built per 256-token window by a two-way page encoder. After the question the model sees only those latents, through one global-read layer.

That single read retrieves facts to 128k: lookup 94 %, recall of 16 facts 91 %, decoys 89 %, all first-letter accuracy. With an order code it also follows a chain stored in order (84 % at 128k).

It fails when facts must be combined. Example: four shuffled chains, "start at A, where do you end?" Every memory and even the dense 30M model stay at 25–45 %, where 25 % is chance. Four weight-tied repeats of the read, with or without a target for each hop, moved the score by −2 to +6 points.

3 · How the reasoning works there: one anatomy

Strip the names off and these systems share one shape. A state is updated by a small tied block, the input is re-injected at every step, the step's output can become the next step's input, every step gets a target, and something decides when to stop. Hover the parts.

4 · The main ingredients, and where E31 stands

What loops do not do. Ouro (7.7T tokens) measures knowledge capacity at about 2 bits per parameter, with or without looping. Saunshi and the iso-depth scaling study find no gain on closed-book QA. Looping buys manipulation of facts, not storage. For a small long-context model that is the right split: E31's memory holds the facts, and a small reasoning loop uses them. It also explains why our memory scores did not need any loop.

Why our repeated read most likely failed

The literature points to three causes. None has been tested here yet.

1 · The bridge is not a question
Read 1 returns B as the content of the slot "A → B". Hop 2 needs B as a key that matches the slot "B → C", and nothing trains those to line up. DiscoLoop: the bridge entity is "nearly perfectly decodable" after loop 1 but misaligned with its input embedding. Feeding back a discrete embedding of it fixes this.
2 · The memory never computes
Every multi-hop success over a memory either loops over the memory itself (Sleep, ImReasoner, loop + memory) or appends thoughts as new inputs (Coconut, superposition). Our slots are frozen per window, and the question side re-reads the same slots with a nearly unchanged query.
3 · Not enough signal
Coconut without its curriculum scores the same as no chain of thought. Composition is learned late, at about 50× the steps needed to fit (grokking). Search becomes learnable only with balanced hop counts. We trained 4800 steps at fixed depth.

5 · Options for the next experiment: your call

Each option keeps the E31 memory as it is (the best version) and adds reasoning on top. They are ordered by how directly the literature supports them for our failing task.

Placement is a judgement from the review, not a measurement. Right = stronger evidence that the mechanism solves multi-hop composition. Up = closer to the vision (reasoning inside the concept memory, small and long-context).

0 · Diagnostic (1 day, no new architecture)

probe the existing checkpoints
  • After read 1 on a chain, is the bridge node B decodable from the question state? Does that state, used as a query, hit B's slot?
  • Run the dense model and E31 with explicit node tokens: the model writes B, C, D as letters before the answer. This is a ceiling. If E31 cannot solve the chain even with an explicit scratchpad, the memory's keys are the problem, not reasoning.
Answers: which of causes 1–3 is real.

A · Thought tokens over the memory ★ recommended

Coconut / reasoning by superposition, on top of E31
  • After QUERY the model emits k latent thoughts. Each thought is its last hidden state fed back as the next input, and each passes through the global read again. That gives k dependent reads, where the output is the next input.
  • Curriculum: explicit node tokens first, then replace them one stage at a time with thoughts. Our generator knows every chain node, so the steps are free.
  • Proof: 2 layers plus D thoughts solve reachability, with a frontier held in superposition. Coconut ProsQA: 97 % vs 77 % for chain of thought.
Cost: small code change (thought positions after QUERY). k extra reads per question.

B · Memory consolidation loop

Sleep / loop + memory / the latent loop
  • Latents of different windows attend to each other for R rounds and update their state, so composed facts (A → C) are written into the memory itself. A question-conditioned variant loops only over the top-k pages the question picks.
  • This is reasoning in the concept space, the closest match to the vision, and the result is reusable by many questions and by agents.
  • Evidence is thinner: synthetic k-hop, where loops must be at least the number of hops. Cost grows with memory size, so it needs windows or top-k.
Cost: medium (a new latent-to-latent block).

C · Recursive reasoning core

TRM / Huginn recipe on the question side
  • A tiny tied block holds a scratch state z and an answer state y. It re-reads the memory and re-injects the question every step. Deep supervision on every step, random depth, gradient through the last cycle, sandwich norms.
  • It fixes everything E33 lacked except feeding the output back as a token.
  • Strong on puzzles and math. The only direct language test (autoregressive TRM) found no reliable gain.
Cost: medium. Can be combined with A later.
My suggested order: 0 (diagnostic) → A, explicit nodes then latent thoughts, on the parallel chain at 1k, with lookup and recall as "do no harm" controls → B if A works and we want the reasoning inside the memory. The decision is yours. The main fork is A (reason in the token stream, best proven) versus B (reason inside the memory, closest to the vision).
