Solvability hunt, not an E21 score. H=128 packed 512 `chain_ordered` was **K1**
(dense 24.2% / 0 bits). Use the width that kept E18 alive at 1024 INDEX
(**H=256 `--global_logit_scale log`**). If that is also K1, one bump:

## Interpretation

**Packed 512 `chain_ordered` (24-token / 48-bit keys, hops=2) is not dense-solvable
at H=128, H=256 SSMax-log, or H=512 full MHA.** This is still an instrument/S0
failure, not a hops verdict for exclusive identity.

Tiny chain (seq=128, packed answer **13** / **26 bits**) was dense-solvable at
H=128 (93%). E24 already had 512 `chain_ordered` K1 at H=128 and H=256 (spread
body). Right-align + packed 48-bit keys + the 1024-INDEX width does not repair
it. Width is not the remaining lever.

## Decision

Keep the spec in `ahead/`. Next ONE experiment: seq=512 `chain_ordered`
**tiny-pack keys** — `--key_len 13` (26-bit prize, same hops as tiny) at H=256
`--global_logit_scale log`, dense-first. Isolates 512 *context* vs 24-token
packed keys. Skip E21 until S0 PASSes. Not 4k. Not Glyph. Not a third width.
