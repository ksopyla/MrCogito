## Goal

H=512 MHA). `--key_len 13` is the tiny packed key: `chain_ordered.answer_len =

width.

## Interpretation

**Tiny 26-bit keys still fail at seq=512.** Key packing (24-token / 48-bit vs
13-token / 26-bit) is **not** the remaining S0 lever. Tiny chain is dense-solvable
at seq=128; the same hops=2 DFA in a 512 body is not, at H=256 SSMax log.

512 **context** (right-aligned hops in a 512-token row) is the remaining S0
question. Width already failed. Packed key length already failed.

## Decision

Keep the spec in `ahead/`. Next ONE experiment (not run this turn): seq=**256**
`chain_ordered --key_len 13` (hops=2, tiny 26-bit keys) H=256
`--global_logit_scale log`, dense-first. Isolates where between seq=128 (S0
PASS) and seq=512 (S0 FAIL) the dense hops wall appears. `--hops 1` is illegal
(`chain needs hops >= 2`). Skip E21 until S0 PASSes. Not 4k. Not Glyph. Not a
third width.
