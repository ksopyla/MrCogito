## Interpretation

512 INDEX failure is **not** "too many r=16 slots." Eight mean-pool slots (tiny's live
width) are still a dead exclusive read at seq=512, while raw E18 keys copy 64 bits in 300
steps. Slot cardinality is ruled out. Remainder stays off.

## Decision

Keep the spec in `ahead/`. Next ONE experiment: **`--message_ratio 1`** (identity slots,
exclusive QUERY cut still on). If that PASSES, compression is the 512 killer; if it stays
at chance, the exclusive message mask is the killer even with full token KV. Not remainder.
Not Glyph. Not 1024.
